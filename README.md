# 家庭调酒酒单小程序

一个以“先建立自己的酒单”为起点的原生微信小程序 MVP。配方中的材料会自动进入材料库，酒单可以按准备方式和材料状态筛选；水果、奶制品、果汁等鲜材可以快速加入手头、标记用完并撤销。

## 导入与运行

1. 安装并打开微信开发者工具，选择“导入项目”。
2. 项目目录选择本仓库根目录（包含 `project.config.json` 的目录），不要只选择 `miniprogram/`。
3. 当前 `project.config.json` 已保存开发者工具生成的测试号 AppID，可直接用于本地体验。如果开发者工具提示重新选择，请点击“测试号”；真机预览、上传或使用正式能力时，再换成自己小程序的正式 AppID。
4. 导入后编译即可。项目没有 npm 运行时依赖，不需要在开发者工具中“构建 npm”。

当前 `project.config.json` 已将 `miniprogramRoot` 指向 `miniprogram/`，入口页是“酒单”，底部导航为“酒单 / 材料 / 我的”。

## 自动化检查

需要 Node.js 24 或兼容 Node 内置测试运行器的版本：

```bash
npm test
npm run check
```

- `npm test`：运行领域规则、仓库、页面模型和集成主路径测试。
- `npm run check`：先递归检查小程序 JavaScript 语法，再运行全部测试。

## 已实现功能

- 快捷建立个人酒单：五种常用基酒、默认酸甜材料、材料搜索/新建、准备方式、杯具、用具、步骤、评价与观察记录。
- 固定准备标签与提前时长，支持准备方式、材料条件、添加时间、评价和名称排序。
- 三态材料语义：当前可用、随买随用但未准备、长期材料当前没有。
- 配方保存时自动建立或复用材料；完整材料库可维护长期材料“我有/我没有”。
- 手头鲜材可记录余量和到期日，支持“看能做什么”“用完”和 6 秒内撤销。
- 材料详情展示使用数、买后立即解锁数、关联酒款、所需杯具和用具。
- 杯具和自定义用具管理；杯具容量参与成品容量提醒。
- 根据液体材料计算预计体积与预估酒精度；计算资料不全时明确提示，不用错误的 0 代替。
- 酒款图片与杯具图片在选择时复制到小程序用户数据目录，再保存其持久路径；不会依赖临时选图路径。

## 本地数据与清空

MVP 不要求登录，所有业务数据只保存在当前微信小程序实例的本地 Storage：

- Storage key：`home-cocktail-state`
- 当前 schema：`version: 1`
- 顶层集合：`recipes`、`materials`、`glassware`、`tools`
- 启动时由 `miniprogram/services/schema.js` 迁移旧数据，页面统一通过 `miniprogram/services/repository.js` 读写，不直接访问 Storage。

要清空开发数据，在微信开发者工具的“调试器 → Storage”中删除 `home-cocktail-state`，然后重新编译。也可以使用开发者工具的“清缓存 → 清除数据缓存”。此操作不可撤销，MVP 没有在小程序内提供危险的“一键清空”入口。

图片文件位于 `wx.env.USER_DATA_PATH` 下的 `cocktail-recipes/` 与 `cocktail-glassware/` 目录。清除 Storage 不一定同时删除这些文件；开发调试时如需彻底重置，请使用开发者工具清除全部数据缓存。正式使用时不要手动编辑这些目录。

## MVP 限制

- 无账号登录、云同步或多设备数据合并。
- 无小红书解析、文字识别、截图 OCR、AI 配方拆解和公共配方库。
- 不自动扣减库存，不记录每次调制；鲜材余量由用户手动维护。
- 每种鲜材只维护一份当前库存，不支持多批次和批次级保质期。
- 固体或其他非 `ml` 的非酒精材料不计入预计液体体积和酒精度分母；水果只有以 `ml` 记录时才计入。
- “补满”在 MVP 中固定按 `100ml` 估算。
- 含酒精材料若缺少 ABV，或以非 `ml` 用量记录，会显示“暂无法完整计算”。
- 图片只保存在当前小程序实例的本地用户数据目录，不会云端备份或跨设备同步。
