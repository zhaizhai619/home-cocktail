# 配方录入酒杯选择页设计

## 目标

将配方录入页的微信原生杯具滚动选择器替换为独立的酒杯选择页。杯具较多时，用户仍能清楚地看到每个杯子的名称和容量，并能一次点击完成选择。

## 已确认交互

- 配方录入页的杯具字段展示酒杯库中的统一名称，格式为“名称-容量ml”。
- 点击杯具字段进入独立选择页。
- 选择页使用与“我的吧台—酒杯”一致的两列卡片布局。
- 第一张卡片为“暂不选择酒杯”，用于清空当前选择。
- 当前选中的酒杯使用描边和底色标识。
- 点击任意卡片后立即选择并返回配方录入页，不增加确认按钮。
- 选择页只负责选择，不提供新增、编辑或删除，避免误操作并保持页面职责单一。

## 数据与页面关系

- 选择页每次打开时从 repository 读取最新酒杯列表。
- 在共享 domain 层提供唯一的酒杯展示 formatter：有效容量显示“名称-容量ml”，历史非法容量显示“名称-容量待补充”。吧台页、选择页和配方录入页都调用它，不各自拼接字符串。
- 配方录入页使用 `wx.navigateTo` 打开选择页，并通过同一个 `EventChannel` 双向通信：打开成功后发送 `glassware:init`，载荷为 `{ selectedId: string }`；选择页点击卡片后发送 `glassware:selected`，载荷为 `{ glasswareId: string }`，随后调用 `wx.navigateBack`。
- “暂不选择酒杯”的 `glasswareId` 明确为空字符串 `''`。用户使用系统返回或手势返回时不发送 `glassware:selected`，原值不变。
- 配方录入页在页面栈中保持存活；接收事件时只更新 `form.glasswareId`。从选择页返回触发 `onShow` 时允许刷新材料、酒杯和用具的引用数据，但不得重新读取配方、重建空表单或清除当前草稿、动态材料行、校验状态。
- 酒杯名称或容量后续在吧台中修改时，配方编辑页从 repository 最新数据和共享 formatter 重新计算展示文字，不把名称或容量复制进配方。

## 边界处理

- 已选择但后来被删除的酒杯继续沿用现有“资料缺失”保存保护。选择页顶部提示“当前选择的酒杯资料已缺失”，不伪造库内卡片，也不静默清空；用户可直接返回保留原值、选择新酒杯替换，或选择“暂不选择酒杯”主动清空。
- 空酒杯库仍展示“暂不选择酒杯”和纯文字提示“请先到我的吧台—酒杯添加”，不提供跨页添加按钮，避免增加页面栈和草稿恢复复杂度。
- 选择页使用原生导航和纵向滚动。内容左右边距为 `28rpx`，两列间距为 `12rpx`，行间距为 `14rpx`；卡片与“暂不选择酒杯”使用相同尺寸，最小高度 `176rpx`，完整卡片均可点击且点击高度不低于 `88rpx`。
- 过长名称单行省略，完整“名称-容量”写入无障碍标签。滚动内容底部留白使用 `calc(40rpx + env(safe-area-inset-bottom))`，以微信开发者工具 iPhone 15 Pro Max 视口验收两列对齐、滚动和底部安全区。

## 验证

- 模型测试覆盖共享 formatter 的有效容量、历史非法容量，并断言吧台、选择页和配方录入页使用同一结果。
- 页面契约测试覆盖新路由、`EventChannel` 事件名与载荷、不再使用原生杯具 picker、选择事件只发送一次。
- 行为测试覆盖选择酒杯、清空酒杯、系统返回不改值，以及往返后保留配方其他字段、动态材料行和校验状态。
- 孤儿杯具测试覆盖直接返回保留、选新杯替换、主动清空及未处理时保存阻断。
- 空库测试覆盖仍可清空当前选择、提示文字正确且不提供编辑入口。
- 无障碍和样式契约覆盖长名称标签、单行省略、两列尺寸与安全区；在微信开发者工具中以 iPhone 15 Pro Max 机型检查选择页和返回流程。
