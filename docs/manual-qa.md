# MVP 人工验收记录

依据 `docs/调酒小程序-PRD-v0.1.md` 第 13 节。记录日期：2026-07-20。

## 本环境结论

当前环境未发现微信开发者工具应用或可执行 CLI，因此没有伪造编译器、模拟器或真机 UI 的 PASS。自动化测试已经覆盖仓库持久化、材料自动生成、筛选组合、详情组装、材料观察、鲜材用完/撤销和杯具容量等主路径；路由、JSON、WXML 事件处理函数和页面不直读 Storage 也已做静态合同检查。下表中的“待用户本机验证”需要在已安装微信开发者工具的 Mac/Windows 电脑上完成。

建议准备一份全新本地数据，并预先在“我的”中新建容量不小于 `200ml` 的杯具“海波杯”。

## PRD 第 13 节主路径（17 步）

| # | 前置 | 操作 | 期望结果 | 本环境结果 |
|---|---|---|---|---|
| 1 | 清空 `home-cocktail-state` 后重新编译 | 进入小程序，点击“录入我的第一款酒” | 首屏为酒单空状态，可直接进入新增配方，不要求先建材料库 | 路由/空状态静态已验证；UI 待用户本机验证 |
| 2 | 位于新增配方页 | 点击快捷基酒“金酒”，填写 `40ml` | 配方出现一行金酒，默认液体、`ml`、含酒精且 ABV 为 40% | 领域与表单模型自动化已验证；UI 待用户本机验证 |
| 3 | 默认酸甜材料仍在表单 | 将柠檬汁替换为青柠汁，青柠汁填 `20ml`，糖浆填 `20ml` | 名称替换不丢失用量/单位，两个液体默认 `ml` | 表单模型自动化已验证；UI 待用户本机验证 |
| 4 | 位于材料区 | 搜索/新建“西瓜”和“紫罗兰利口酒”，分别填 `100ml`、`10ml`；紫罗兰利口酒 ABV 填 `20%` | 西瓜默认为随买随用鲜材；利口酒默认为长期材料且当前没有 | 集成主路径自动化已验证；UI 待用户本机验证 |
| 5 | 配方材料已完整 | 选择“冷冻”，填写 `1 天` | 即调被排除，准备记录为冷冻 1 天 | 准备规则自动化已验证；UI 待用户本机验证 |
| 6 | “我的”中已有海波杯 | 在杯具选择器中选择海波杯 | 配方保存稳定的杯具 ID，并显示杯具名称 | 装备水合自动化已验证；UI 待用户本机验证 |
| 7 | 金酒 40ml、青柠汁 20ml、糖浆 20ml、西瓜 100ml、利口酒 10ml；杯具已选 | 查看“杯具与酒精度”预览 | 显示预计液体体积、容量提醒和“预估酒精度 XX%”；资料缺失时显示待补充而不是 0 | ABV/容量自动化已验证；具体排版待用户本机验证 |
| 8 | 表单校验通过 | 点击“保存配方”，返回酒单 | 酒单出现该酒，合并标签统一显示“冷冻 · 提前1天” | 集成/标签自动化已验证；UI 待用户本机验证 |
| 9 | 西瓜尚未加入手头，紫罗兰利口酒为“我没有” | 查看酒单卡片及详情材料行 | 紫罗兰利口酒只使用可读灰态，不增加缺失装饰或状态文字；西瓜为暖色并带购物袋图标，不显示“需购”等状态文字 | 视图模型/可访问性合同已验证；视觉待用户本机验证 |
| 10 | 配方已保存 | 切换到“材料” | 金酒、青柠汁、糖浆、西瓜和紫罗兰利口酒均自动出现在材料库 | 仓库集成自动化已验证；UI 待用户本机验证 |
| 11 | 材料库已生成 | 打开紫罗兰利口酒详情 | 显示被几款酒使用，以及购买后立即解锁几款 | 关系统计自动化已验证；UI 待用户本机验证 |
| 12 | 位于西瓜卡片或详情 | 点击“加入鲜材”，填 `500g` 和未来到期日并确认 | 西瓜进入手头鲜材，显示“还剩约 500g”和到期提示 | 鲜材仓库/日期模型自动化已验证；UI 待用户本机验证 |
| 13 | 西瓜在手头 | 点击“看能做什么” | 打开西瓜详情，列出所有含西瓜的酒；每款显示材料、杯具和用具，并能打开酒款详情 | 关联详情模型/路由静态已验证；UI 待用户本机验证 |
| 14 | 西瓜在手头 | 点击“用完”，再观察撤销条；可额外点一次“撤销”验证恢复 | 西瓜只移出手头鲜材；材料和关联酒款保留；6 秒内可撤销 | 用完/撤销集成自动化已验证；计时与 UI 待用户本机验证 |
| 15 | 酒单至少有不同准备时长的多款酒 | 选择“冷冻”，排序选“准备时间最短” | 只显示含冷冻准备的酒，并按换算后的提前时长升序排列 | 筛选/排序自动化已验证；UI 待用户本机验证 |
| 16 | 紫罗兰利口酒标为“我有”，西瓜当前不在手头 | 先选“手头就能做”，再选“补点鲜材就能做” | 前者不显示这款酒；后者显示这款酒 | 集成主路径自动化已验证；UI 待用户本机验证 |
| 17 | 另有一款“即调”且只缺随买随用鲜材的酒 | 同时选择准备标签“即调”和材料条件“补点鲜材就能做” | 两个条件同时生效，只显示同时满足的酒 | 组合筛选自动化已验证；UI 待用户本机验证 |

## 回归边界

| 边界 | 操作 | 期望 | 当前验证 |
|---|---|---|---|
| 异常 Storage | 在自动化适配器中令下一次写入失败 | 材料、配方、鲜材、杯具和用具写入不留下半成功内存状态；页面提示重试 | 自动化已验证 |
| 旧数据迁移 | 用缺字段、重复 ID、旧杯具容量字段和冲突固定用具 ID 的状态启动 | 幂等迁移到 schema v1，保留用户字段并修复引用 | 自动化已验证 |
| 图片 | 为酒款和杯具分别选择本地临时图片，重启编译后再次打开详情 | 显示来自 `wx.env.USER_DATA_PATH` 管理目录的持久图片；不使用临时路径 | 服务自动化已验证；重启 UI 待用户本机验证 |
| 时区与日期 | 在接近午夜时设置鲜材到期日并切换设备时区 | 到期提示按设备本地日历日计算，不按已过小时数误差一天 | 日期模型自动化已验证；多设备 UI 待用户本机验证 |
| 计算边界 | 混用 `ml`、固体单位、含酒精非 `ml`、缺 ABV 和“补满” | 固体非 `ml` 忽略；含酒精不可计算项阻止完整结果；补满按 100ml | 自动化已验证 |
